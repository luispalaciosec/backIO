# 15 · Capa de IA

> Sprint 4 del plan v2. Estado: **en producción desde 04/09/2026**.

## Principio

La IA **redacta, nunca publica**. Todo texto generado lo revisa y publica una persona, y va firmado
"Redactado por BackIO, publicado por [persona]". El modelo recibe **únicamente datos estructurados de
BackIO** (títulos, estados, fechas, números, horas). El texto de Basecamp nunca entra a BackIO, así que
no puede llegar al modelo (regla 1 de `CLAUDE.md`).

Módulo: `backend/src/lib/ia/`. Un solo punto de entrada a Anthropic (`generarTexto` / `generarJson`,
modelo `claude-sonnet-5`). Cada generación queda en `ia_generaciones` con el hash del payload
(caché + auditoría, tokens de entrada/salida). Si `ANTHROPIC_API_KEY` no está, los botones ✨ no aparecen.

## Casos de uso

| Caso | Dónde | Qué recibe la IA | Qué devuelve | Quién publica |
|---|---|---|---|---|
| **Daily narrado** | Daily → ✨ Redactar apertura / cierre | Las 3 señales del daily acotadas a la mesa + notas del responsable | 3–6 líneas de texto plano, editable | Quien abre/cierra la mesa (Grace, etc.). Va al board Daily con firma |
| **Weekly narrado + agenda por causa** | Weekly → ✨ Agenda IA · casilla "incluir resumen IA en los documentos" | KPIs, salud por cliente, carga por persona, últimas 4 semanas, arrastre, señales agrupadas por causa (agrupación determinista, ver `CAUSAS`) | Narrativa de 2–4 párrafos + una **pregunta de decisión** por causa | Marcia; el Plan/Acta con `?ia=1` lleva el resumen al inicio |
| **Brief → plan** | Builder paso 2 → ✨ Pegar correo del cliente | Texto pegado por la ejecutiva + catálogo de plantillas y tipos de pieza | Brief estructurado, plantilla sugerida, piezas por tipo, dudas para el cliente | La ejecutiva revisa el formulario y crea el proyecto. El texto pegado no se guarda |
| **Recordatorio al cliente** | Backlog → ✉ en filas `pendiente_cliente` o bloqueadas | Solo lo que el cliente puede ver (etiqueta o título visible), días de espera, fecha comprometida | Asunto + cuerpo de correo, 120 palabras | La ejecutiva copia y envía desde su correo. BackIO no escribe al cliente |
| **Informe ejecutivo mensual** | Informes (día 1 de cada mes 08:00 automático, o manual) | Entregas y piezas del mes, a tiempo, horas de Basecamp por cliente y persona, cotizado vs. horas (USD/h), señales por tipo, arrastre | Markdown con "Lectura del mes" + "Lo que hay que decidir" + tablas | Marcia lo publica en el board Weekly de la mesa. Se guarda como acta `informe_mensual` |

MCP: tool de lectura `get_weekly_narrative` (mesa opcional).

## Endpoints

```
GET  /api/v1/ia/estado                       → { disponible, modelo }
POST /api/v1/ia/daily                        { mesa_id, tipo, notas[] } → { texto, resumen }
POST /api/v1/ia/weekly                       { semana_id, mesa_id? } → { narrativa, agenda[{causa, items, pregunta}] }
POST /api/v1/ia/brief                        { texto, cliente_id? } → BriefIA
POST /api/v1/ia/recordatorio/:requerimientoId → { texto, titulo_usado }
POST /api/v1/ia/informe-mensual              { mesa_id, mes: "YYYY-MM" } → Acta
GET  /api/v1/ia/informes                     → { items }
POST /api/v1/semanas/daily/publicar          acepta `narrativa` (texto editado por la persona)
POST /api/v1/semanas/:id/plan|acta?ia=1      antepone el resumen ejecutivo de la IA
```

## Lo que la IA no hace

- No cambia estados, fechas ni prioridades. No crea requerimientos (para eso están las tools MCP con preview + confirm).
- No escribe en Basecamp ni al cliente por sí sola.
- No ve comentarios, descripciones ni adjuntos de Basecamp: nunca existen en BackIO.
